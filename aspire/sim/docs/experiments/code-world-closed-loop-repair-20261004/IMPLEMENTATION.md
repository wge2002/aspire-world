# Code World 闭环修复 — 2026-10-04

本轮完成工程修复及 CPU 验收。没有启动 DLC、仿真试验、感知服务或模型实验调用；不将软件测试结果解释为机器人成功率提升。

## 启用方式和旧版本兼容

新实验显式设置 `closed_loop_revision: r1`，同时保留 `condition: C`、`profile: judgment`、`executable_world_revision: r1`、`foundation_revision: r1`。支持 `full` 和 `no_rehearsal`；与 `no_self_eval` 等不兼容组合在执行前拒绝。原有 fresh/repair lineage 约束继续适用。

旧 foundation 提示与接口文档曾明确要求 done() 只做观测。本轮新增独立版本，新提示明确覆盖旧接口中这一约束；未启用时六种旧提示逐字不变。旧冻结运行环境、程序与结果不修改。未来新实验需要重新冻结包含本轮代码的运行环境，不能向旧冻结批次直接注入新语义。

## 实际改动

1. **实测与预测分离。** 复用 EvidenceState。`observed_only()` 只返回当前 binding 的实测层，逐一检查所有当前证据 ID，避免新观测为旧证据蒙混过关。预测仍可作为搜索线索；它不能通过此接口成为抓取、进展或完成证据。新版本的 query/predicate/done 同步收紧新鲜度；历史参考证据单独处理，旧版本维持原规则。
2. **身份与缺测处理。** `confirm_identity()` 要求新鲜观测、唯一匹配、明确身份及与原目标一致；缺失、歧义或换目标返回 unknown。`invalidate()` 主动清除失效实测，不拿旧位置或预测顶替。生成提示要求后续关联始终传入原身份，不从不完整候选集合的中间索引猜目标。
3. **在线判断接入分支。** 新提示要求在操作关键点 update → query/done → 实际分支。done 返回 `observe/recover/continue/stop`，运行时把缺证据或矛盾的请求降为 unknown/observe。恢复动作和任务判断仍由生成策略负责。策略在线判断与框架最终自评使用明确 origin 标记，异常退出时不会再靠“最后一条记录”猜来源。
4. **管线身份与诊断。** 新版本进入开发身份、试验配置、离线缓存键及 held-out 续跑身份；新旧模式不能混用缓存或冻结账本。静态检查报告被忽略的 world 结果、可见分支及预测层风险；支持常见助手函数/别名写法；这些静态疑点不单独构成阻断，也不消耗试验次数。`no_rehearsal` 继续关闭离线筛查。

未增加动作、恢复或查询次数上限；原开发 51–65、冻结评估 1–50、每开发 seed 三次计费预算保持不变。
